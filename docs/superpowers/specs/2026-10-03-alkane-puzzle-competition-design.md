作成日: 2026-10-03（日本時間）

対象: GitHub Pages + 専用Supabaseによる新規Webアプリ

## 1. 目的と基本方針

AlkanePuzzleのパズル内容と操作感を引き継ぎ、授業で行う「クラスコンペ」と、生徒同士で行う「メイトマッチ」を提供する。競技への参加、部屋管理、開始、中断、結果、レース表示は、GitHub + Supabase版IonicFormulaCompetitionを移植する。

画面のゲーム名は、すべて「並べる」「名付ける」で統一する。「アルカン並べ」「ゲーム①」「ゲーム②」は利用者向けの名称に使わない。難易度は「すいすい」「まあまあ」の2段階とし、「そこそこ」と自由制作の「練習」は採用しない。

2026-10-04に本書に沿う実装が承認された。配色は全面的にAlkanePuzzleへ合わせ、開始前のホスト・ゲストの構成と操作は現在のイオンコンペへ合わせる。Supabase・Google認証など利用者による作業が必要な箇所は、その段階で具体的に案内する。公開は別途承認された段階で行う。

## 3. モードと競技設定

### 3.1 パズル

- **並べる**: 示された名称に合う構造を、パネルを並べて作る。
- **名付ける**: 示された構造図を読み、語群から名称を組み立てる。
- 部屋作成時にどちらかを選ぶ。1競技内に両モードを混在させない。
- マウス、タッチ、長押しによるパネル移動、語句の挿入・削除などは、本家の現行挙動を引き継ぐ。
- 手書きメモ、色、消去、戻す操作、音のON/OFF、正解・誤答の演出も移植する。ただし競技中のヒント・正答開示は第5節のとおり制限する。

### 3.2 共通設定

| 項目 | 選択肢・既定値 |
|---|---|
| 競技形式 | クラスコンペ / メイトマッチ |
| ゲーム | 並べる / 名付ける |
| 難易度 | すいすい / まあまあ |
| 判定方式 | 問題ごと判定 / まとめて判定 |
| 問題数 | 5 / 10 / 15問。既定10問 |
| 制限時間 | 3〜10分、1分刻み。既定5分 |
| アルコール | ON / OFF。既定OFF |
| 最大参加人数 | クラス42名 / メイト4名 |
| 開始前カウントダウン | 5秒 |

新規作成フォームの初期選択は「並べる・すいすい・問題ごと判定・10問・5分・アルコールOFF」とする。メイトマッチの4名には作成者を含める。クラスの教員は解答者の42名に含めない。

アルコールOFFではOHを含む問題を出さず、不要なOHパネル・オール語句の扱いも本家に準じる。ONでは選択された難易度の出題率、OH個数、置換基数への算入設定を適用する。生徒は競技中にモード・難易度・アルコール・問題数・制限時間を変更できない。

### 3.3 クラスコンペとメイトマッチ

クラスコンペは、Google認証と共通教員許可リストで許可された教員が作成する。生徒は参加コードまたはQR・参加リンクとニックネームで参加する。メイトマッチは教員ログインを要求せず、作成者が設定して自分も参加する。

ロビー、ニックネーム変更、参加者除外、開始条件、準備完了の確認、準備の取り消し、ブラウザーの戻る操作からの復帰は、イオンコンペの現行実装を引き継ぐ。準備開始後は新規参加や設定変更を許可しない。

待機中の「終了」は参加と開始を停止し、成績を作成しない。競技中の「中断」はその時点までの記録で結果を確定する操作であり、同じ競技を再開する一時停止ではない。確認モーダルを含め、イオンコンペと同じ操作にする。

## 4. 難易度の調節

### 4.1 教員管理画面

イオンコンペと同様に、マスター教員の「管理設定」から「難易度を調整」モーダルを開く。「並べる」「名付ける」それぞれに「すいすい」「まあまあ」の設定を保持する。一般教員は競技作成時にこれらを選択できるが、共通の詳細設定は編集できない。

詳細設定はアルカン専用Supabaseに保存する。初版はアプリ全体に1組のクラスコンペ用設定を持つ。教員許可リストの共通管理と、ゲームごとの難易度設定の保存先は分ける。

| 調節項目 | 対象・範囲 |
|---|---|
| 主鎖炭素数 | 両モード。最小・最大、1〜10 |
| 置換基・OH基の種類数 | 両モード。最小・最大、1〜6。本家と同じ算入規則 |
| 置換基・OH基の数 | 両モード。最小・最大、0〜10。本家と同じ算入規則 |
| シクロ主鎖の炭素数 | 両モード。4 / 6 / 8 / 10から選択、最低1つ |
| 枠数（横・縦） | 並べる。横3〜7、縦3〜5 |
| 折れ曲がり炭素数 | 名付ける。最小・最大、0〜10 |
| 語群グループの表示順を出題ごとに入れ替える | 名付ける。ON / OFF |
| ヒドロキシ基を出題数に含める | 両モード。ON / OFF |
| アルコール問題の出題率 | 両モード。0〜100%。刻み幅は本家と同じ |
| 分子中のヒドロキシ基を1個までにする | 両モード。ON / OFF |
| シクロにつける置換基の数 | 両モード。0個 / 1個 / 2個以上の単一選択。OHを除く置換基を数える |

「置換基・OH基」のラベルはOHを算入するかどうかで本家と同じように切り替える。アルコールOFF中も、出題率やOHの保存値は保持する。「そこそこ」のタブ、設定、説明は表示しない。初期値へのリセットは選択中のモード・難易度に適用し、競技のアルコールON/OFFは変えない。

シクロの置換基数は従来の「環に置換基を必ず付ける」に代わる設定とする。0個・1個は指定個数に一致させ、2個以上は2個以上の範囲で既存の生成条件と併せて検査する。OH個数とその算入条件は独立して適用する。実現不能な組み合わせを黙って別の条件へ変更しない。

### 4.2 初期値

端末に保存された個人設定ではなく、本家の現行既定値を採用する。

| 項目 | 並べる・すいすい | 並べる・まあまあ | 名付ける・すいすい | 名付ける・まあまあ |
|---|---|---|---|---|
| 主鎖炭素数 | 1〜6 | 4〜8 | 1〜6 | 4〜8 |
| 置換基・OH基の種類数 | 1 | 1〜2 | 1 | 1 |
| 置換基・OH基の数 | 0〜4 | 3〜6 | 0〜4 | 3〜6 |
| シクロ主鎖炭素数 | 4・6 | 6・8 | 4・6 | 6・8 |
| シクロにつける置換基の数 | 0個 | 1個 | 0個 | 1個 |
| 枠数 | 7×5 | 7×5 | 対象外 | 対象外 |
| 折れ曲がり炭素数 | 対象外 | 対象外 | 0〜1 | 2〜3 |
| 語群グループの表示順の入れ替え | 対象外 | 対象外 | OFF | OFF |
| アルコール問題の出題率 | 40% | 40% | 40% | 40% |
| OH基を1個までにする | ON | OFF | ON | OFF |
| OH基を置換基数に算入する | ON | ON | ON | ON |

ハロゲン化メタンを「すいすい」のみに含める規則、鎖状・環状などの抽選比率、重複回避、位置番号の偏りを減らす処理、語群の構成は本家に準じる。抽選比率とアルコール出題率は生成時の確率であり、5問などの少数問題で厳密な個数を保証するものではない。これらの固定規則を新しい調節項目として追加しない。

### 4.3 設定を固定する時点

クラスの部屋作成時に、両モード・両難易度の詳細設定と版番号を部屋にコピーする。管理画面での変更は、その後の新規部屋にだけ適用する。

イオンコンペと同様、部屋の待機中は作成者がゲーム・難易度・アルコールなどの競技設定を変更できる。詳細設定は部屋作成時のコピーから選び、最新の管理設定を勝手に取り直さない。準備開始時に競技設定と問題一式を固定する。

メイトマッチは教員の調節値を使わず、アプリ共通の標準設定を使う。作成者が選べるのは第3.2節の競技設定で、詳細調節はできない。標準設定の更新も、更新後に作成した部屋だけに適用する。

## 5. 解答・採点・順位

### 5.1 正解の扱い

並べるは、本家の構造認識・命名処理によってお題に一致すると判定される構造を正解とする。盤面上の位置、向き、回転、配置の描き方が違うだけでは不正解にしない。正答例の座標配列との完全一致を採点条件にしない。結合・原子価・主鎖・置換基・OHなどの条件は本家に準じる。

名付けるは、本家の語句からの名称復元、命名規則、表記と省略の扱い、正誤判定を引き継ぐ。新しい別名や許容表記を独自追加しない。名称の文字列に限らず、入力した語句列を保存する。

両モードとも1問1点。部分点と誤答回数による減点は設けない。採点対象は解答の構造または名称で、手書きメモは採点しない。

### 5.2 問題ごと判定

「チェック」で判定し、正解・誤答を表示する。誤答時は作りかけの構造・語句を保持して修正できる。正解または「パス」で先へ進む。イオンコンペにあるパスした問題の再挑戦も移植し、競技確定前の正解は1点とする。正解済みの問題は重複加点しない。

競技中は誤答の詳しいヒント、正答表示、「答え」ボタン、正答を示す復習を無効にする。並べるの問題文に必要な名称と、本家にある通常の操作・構造表示は保持する。問題ごとの正誤表示自体は利用できる。

### 5.3 まとめて判定

競技中は正誤・ヒント・正答を表示しない。問題間の移動、見直し、修正、提出確認はイオンコンペと同じにする。並べるの入力中の構造認識を採点結果の表示に使わない。提出後は編集不可とし、時間切れでは受け付け済みの記録を対象に採点する。

### 5.4 順位と計時

正解数の多い順、所要時間の短い順に順位を決める。同じ正解数・同じ時間（1/100秒単位）なら同順位とし、次順位を飛ばす。表示順は参加順で安定させる。パス・未解答は0点。

競技開始、締切、提出時刻、通信待ちの扱い、操作記録の検証、時間切れと中断時の時間算出は、イオンコンペの現行計時処理を再利用する。再接続によって競技の締切を延長しない。通信待ちに関する既存の限定的な所要時間補正と、競技全体の締切を延長することを区別する。

確定した得点・時間・順位はサーバーの検証結果を正とし、クライアントから申告された得点をそのまま保存しない。再送や重複送信で加点、提出、時刻確定が二重に実行されないようにする。

## 6. 問題生成と公平性

同じ部屋では全員に同じ問題を同じ順番で出す。名付けるの構造図の向き・折れ曲がり・位置も統一する。語群グループや語群内部の並びをランダム化する場合も、問題ごとに確定し参加者間で一致させる。画面サイズによる折り返しは許容するが、論理上の並びは変えない。

準備開始時に部屋の設定から問題一式を生成し、構造データ、名称、表示用データ、語群、採点版番号を保存する。各生徒の端末で別々に問題を抽選しない。再読み込みや再接続でも同じ問題を復元する。

設定保存時に範囲と組み合わせを検査する。問題生成は回数・時間に上限を設け、生成結果が設定と採点条件を満たすことを確認する。本家の最終保険用の問題を、設定外のまま競技問題として採用しない。必要数を用意できなければ開始を止め、理由と見直す設定を表示し、待機状態へ戻れるようにする。設定を黙って緩めない。

本家の重複回避を維持するが、狭い設定で15問の完全非重複を保証しない。生成不能と単なる重複を区別し、解けない問題や停止を防ぐことを優先する。

## 7. 通信断・再読み込み・途中解答の復元

### 7.1 保存する内容

| モード | 復元対象 |
|---|---|
| 共通 | 部屋・参加者・問題一式の識別子、設定/採点版、現在の問題、確定済み解答、未送信操作、送信済み位置、終了状態 |
| 並べる | 問題ごとの盤面パネル、種類・向き・位置、最新の完了した編集状態 |
| 名付ける | 問題ごとの語句列、挿入位置、最新の完了した編集状態 |
| 手書きメモ | 同一端末で復元する問題ごとの線データ。ローカル保存のみ |

盤面・語句の編集が完了するたびに、IndexedDBへ保存する。パネルの移動途中や、ペンが接触中の線の途中までの復元は保証対象外。高頻度のpointer移動を1件ずつサーバーへ記録しない。

途中解答はサーバーにも同期する。オンライン時は最新変更をまとめ、最後の変更から最大2秒以内に送信を試みる。チェック、パス、問題移動、提出では、その操作に必要な解答を一緒に送る。未確認の送信を成功扱いせず、「端末に保存済み」「同期中」「同期済み」などの状態を区別する。

### 7.2 復元と競合

同じブラウザーの有効な参加資格で復帰した場合に、進行と途中解答を復元する。部屋、参加者、問題一式、採点版、書き込み世代が一致する記録だけを復元し、別の部屋や古い問題のデータを混ぜない。

ローカルの未送信操作とサーバーの受領済み位置を照合して、同じ操作IDで再送する。古いサーバーの途中解答で、より新しいローカル解答を上書きしない。二重タブ・端末競合はイオンコンペの書き込み権限管理を引き継ぎ、別の書き込み世代の解答を黙って統合しない。

既に準備完了している競技では、一時的な通信断中も取得済み問題の編集を継続できる。締切・中断後は新しい編集を受け付けない。記録回収の猶予と採用条件はイオンコンペに合わせ、猶予時間を追加の解答時間として使わせない。提出送信が未確認なら、送信確認中として表示する。

保存領域の消去、プライベートブラウズ終了、参加資格の紛失、別端末への移動後の同一参加者としての復旧は保証しない。新規参加で別の人に既存解答を渡さない。保存領域が使えない場合は、復元機能を利用できない旨を表示し、保存できたと誤表示しない。

## 8. 結果・復習・レース

結果画面、順位公開のタイミング、個人成績、教員の一覧、過去の競技、読み込み失敗時の再試行、ホームへの導線は、イオンコンペの現行構成に合わせる。

個人復習では、お題、自分の最終解答、正誤、正答・説明を表示する。並べるは自分の構造と正答例を表示し、正答例には「配置の一例」と分かる文言を付ける。名付けるは構造図、自分の語句列・名称、正答名称を表示する。詳しいヒントは復習で使用できる。

レースは同じ表示・動き・軽量表示・スクロールを移植し、UIの配色はAlkanePuzzleへ合わせる。参加者識別用の多色ランナーは既存方式を維持する。問題ごと判定では「正解数 / 問題数」、まとめて判定では「解答を入力した問題数 / 問題数」を進捗とする。編集回数や現在の問題番号を進捗にしない。

まとめて判定の入力済みは、並べるでは盤面に1個以上のパネルがある問題、名付けるでは語句が1個以上ある問題とする。すべて消した問題は入力済みから外す。構造として不正でも入力があれば入力済みとし、競技中の正誤は漏らさない。レースの暫定順と、最終成績による順位を区別する。

## 9. 専用Supabaseと共通教員許可リスト

### 9.1 分担

| 保存先 | データと役割 |
|---|---|
| アルカン専用Supabase | アルカンのAuthセッション、部屋、参加者、問題、解答、結果、詳細難易度設定、Realtime、保守 |
| 既存イオンコンペSupabase | 共通教員許可リストと共通マスター教員の管理元 |
| 各アプリのブラウザー | そのアプリ専用の参加資格と途中解答・表示設定・手書きメモ |

初版では第三のSupabaseプロジェクトを作らず、既存イオンコンペの許可リストを共通の正とする。アルカン側へ許可リストの手動コピーや独立編集用の複製を作らない。競技データと難易度設定はアプリ間で共有しない。メイトマッチの有効・無効もアプリごとに管理する。

### 9.2 共通認可の設計

既存イオンコンペに、サーバー間通信専用の共通教員認可APIを追加する。アルカンのバックエンドは自分のプロジェクトで検証したGoogle認証セッションを用いて、共通管理元へ利用可否を照会する。管理元も登録済み呼出元プロジェクトのAuthでトークンとGoogleの確認済みメールを検証し、共通許可リストと照合する。

ブラウザーが送ったメール文字列、ヘッダー、ローカル設定だけでは教員権限を与えない。呼出元プロジェクトとAuth URLはサーバーの登録値から選び、任意URLを入力として受け取らない。サーバー間の呼び出しにはアプリ別の秘密による署名、時刻、有効期限、再送識別を付け、秘密はブラウザーやGitHubへ含めない。

両アプリの許可リスト画面は同じ管理元を操作する。閲覧・追加・無効化は共通マスターだけに許可し、一般教員には他の教員のメール一覧を開示しない。更新は管理元の版番号と操作IDで競合・二重更新を防ぐ。「この変更はイオンコンペとアルカンコンペの両方に適用されます」と画面に表示する。

共通の本人照合は確認済みメール、本アプリ内の部屋所有者は当該プロジェクトのAuthユーザーIDで扱う。別プロジェクトのAuthユーザーIDが同じであることを前提にせず、アルカンのユーザーIDを既存イオンコンペの教員紐付け表へ登録しない。

教員の管理API操作ごとに利用可否を確認し、許可を外された教員の次の操作を拒否する。Realtimeの教員閲覧権限には最長60秒の認可期限を設け、再照会によって更新する。認可情報の紐付けは専用DBに保持できるが、許可リストの正として扱わない。

共通管理元へ照会できない場合は、新たな教員権限と管理操作を許可せず、再試行できるエラーを表示する。許可情報が不明なことと、明示的な許可取り消しを区別する。既に開始した競技の生徒の編集・解答・自動締切・結果確定は、共通管理元に依存させない。一般参加者のAPIごとに共通認可を照会しない。

### 9.3 既存アプリへの必要な変更

共通認可API、共通管理である旨の表示、共通認可の検証だけを追加する。既存の許可リストを別表へ移す必要はなく、既存の教員・競技・結果を削除しない。イオンコンペのGoogleログイン、教員登録、作成、開始、結果、許可取り消しへの回帰確認を必須とする。

許可リストの共通管理はログインセッションの共通化ではない。各アプリでGoogleログインを行う。新プロジェクトのOAuthコールバックとPagesへのリダイレクトを登録する。既存プロジェクトの認証設定を上書きしない。

## 10. 保存期間と容量

### 10.1 保存対象と期間

「結果の記録」は参加者ニックネーム、得点、所要時間、順位、問題、解答、復習用データ、関連する途中解答と操作記録を含む。初期設定はクラス・メイトとも、競技終了または中断で結果が確定してから14日間とする。

待機したままの部屋は2時間、開始前に終了した部屋は1日で期限切れとする。異常終了で結果が確定しない部屋は競技締切から採用中の保存期間が経過した時点で期限切れにし、準備中に止まった部屋は作成から2時間で期限切れにする。教員許可リストと難易度設定は競技結果の14日削除対象に含めない。

競技ごとに保存期限を確定して表示する。期限到達後はAPIから参照できなくし、15分間隔の定期清掃とリクエスト時の補助清掃で、期限切れの部屋と子データを小分けに削除する。無アクセスでも清掃が進む構成にする。清掃の遅延・失敗を監視する。Supabase側で保持されるバックアップやサービスログの寿命は、アプリの参照期限・表の削除とは分けて運用記録に残す。

途中解答は最新状態を更新し、ドラッグ履歴の全座標や画像を蓄積しない。部屋共通の問題を参加者ごとに複製しない。確定後は再送確認に必要な期間を過ぎた作業用データを整理し、復習用の最終解答は保存期限まで保持する。

### 10.2 容量に応じた短縮

公開前に実際のプラン・使用量と、42名×15問の両モードの実データ量を測り、問題、解答、索引、操作記録、Auth・通知関連の増加を含めて14日分を見積もる。専用プロジェクトを作っただけで、容量や組織側の上限に余裕があると判断しない。

14日では余裕が不足する場合、ユーザーの了承済み範囲として初期保存期間を7日、さらに必要なら1日に短縮できる。採用期間と測定根拠を公開前の実装記録と利用画面に明記する。有料プランへの変更は本書の範囲に含めない。

公開後の期間変更は新しい競技から適用し、既に表示した保存期限を黙って前倒ししない。期限前の記録をまとめて削除する必要が生じた場合は、対象と件数を提示して別途確認する。

### 10.3 Authと端末内データ

競技データの削除と匿名Authユーザーの削除は別に管理する。アルカン専用プロジェクト内で、匿名・教員identityなし・保存期間内の結果や有効な参加資格なし・最終利用から14日以上を満たすユーザーを保守候補とする。最終利用を確認できないユーザーは候補から除外する。初版は候補点検と件数の記録を用意し、Authの削除は対象と件数を確認した管理者の保守操作で行う。削除直前にも保護条件を再確認し、教員Authと他プロジェクトのユーザーを対象にしない。

端末内の解答・メモにも部屋の期限を付け、起動・復帰時に期限切れデータを清掃する。閉じたブラウザーの保存領域をサーバーから直接削除できるとは扱わない。ニックネームなどの参加補助設定と競技記録を区別し、イオンコンペと混ざらない保存キーを使う。

## 11. 実装構成とデータ契約

フロントエンドはイオンコンペのReact + TypeScript + Vite構成を移植し、GitHub Pagesで配信する。バックエンドは専用SupabaseのEdge Functions、PostgreSQL、private Realtimeを使用する。DB接続は専用プロジェクトのpoolerを確認し、EdgeとDBの配置による待ち時間を計測する。

アプリ内で、競技共通処理とアルカン固有処理を分ける。初版で両アプリを同じデプロイや共通npmパッケージに統合しない。

- **競技共通処理**: 参加資格、部屋状態、開始・締切、操作ID、再送、書き込み権限、順位、結果、通知。
- **アルカン固有処理**: 設定検証、問題生成、構造と語句の正規化・判定、盤面・語群・メモの表示、復習。
- **共通教員認可**: 本人確認、共通許可リスト、マスター権限。競技DBのトランザクションを保持したまま外部照会しない。

本家HTMLから、生成・命名・判定の純粋な処理をDOM・音・表示状態から分離し、クライアントとサーバーの両方で同じ版の処理を利用できるようにする。本家の操作UIをReact化する場合も、外観と操作を移植の受け入れ条件とする。HTML全体を埋め込み、別のゲーム状態が独立して動く構成にしない。

主要データは次の単位で持つ。名称や型の詳細は実装計画で確定するが、責任と保持条件は変えない。

| データ | 契約 |
|---|---|
| 部屋 | 形式、所有者、選択設定、作成時詳細設定、設定版、状態、開始・締切・保存期限 |
| 問題一式 | 部屋・準備世代、ゲーム版・採点版、問題順、構造、お題、語群の確定順 |
| 問題解答 | 並べるの盤面JSON、または名付けるの語句列JSON。1問1解答 |
| 途中解答 | 参加者・問題・書き込み世代ごとの最新解答、編集版、受領済み位置 |
| 操作・受領票 | 一意ID、順番、版、操作種別、解答、競技内時刻。再送で同じ結果 |
| 最終結果 | 最終解答、正誤、得点、時間、順位。確定後に同じ操作で再計算しない |

入力は配列長、盤面サイズ、パネル種別、向き、座標、語句の許可値、JSONサイズを検査する。手書きメモ・SVG・画像・pointerイベント列を採点APIの入力にしない。ブラウザーに秘密キーを置かず、RLS・直接権限・API・private通知を、部屋所有者と参加者の権限に合わせる。通知は状態変更の案内と集計に用い、欠落時はHTTPで正しい状態を再取得する。

問題ごと判定に必要なローカル判定データの扱いはイオンコンペの現行方式に合わせ、ヒント・正答開示の無効化は通常画面での競技ルールとして実装する。ブラウザー開発者ツールによる解析まで防ぐ不正対策を達成したとは主張しない。

## 12. 受け入れ条件と検証

### 12.1 パズルと設定

1. ゲーム名が「並べる」「名付ける」、難易度が「すいすい」「まあまあ」で統一され、対象外モードが出ない。
2. 本家と代表的な鎖状・環状・置換基・OH問題の生成・命名・判定が一致する。
3. 並べるの位置・向き・回転違いを正しく受け入れ、結合や原子価の異常を本家と同じ基準で判定する。
4. 難易度モーダルの全項目、初期値、保存、再読み込み、リセット、権限制限が動く。
5. アルコールOFFでOH問題が出ず、ONで出題率・OH個数・算入規則が働く。
6. 管理設定の変更後も既存部屋の設定と問題が変わらず、メイトには共通標準設定が適用される。
7. 生成不能な設定で準備が停止して理由を表示し、問題不足のまま開始しない。

### 12.2 競技と復元

8. 両ゲーム×両判定方式で、クラス・メイトの作成、参加、準備、開始、提出、中断、結果、復習が動く。
9. 同じ部屋の問題・構造図・語群順が参加者間と再読み込み前後で一致する。
10. 正解1点、誤答の修正、パスと再挑戦、未解答、同順位、時間切れが仕様どおりに扱われる。
11. 競技中のヒント・正答開示を使えず、まとめて判定では正誤を表示しない。
12. パネルを複数配置した途中状態、語句を複数入力した途中状態を、問題移動・再読み込み・ブラウザーの戻る・通信断後に復元できる。
13. 未送信データ、サーバーだけにある途中解答、重複再送、二重タブ、古い版の復元を検査し、加点や提出が二重にならない。
14. 復帰で締切が延びず、時間切れ後の新しい編集が得点に混ざらない。
15. 中断後の結果が教員・生徒で一致し、中断した競技は再開できない。
16. レースの分子と最終順位が仕様に一致し、入力の全消去も正しく反映される。

### 12.3 認証・運用

17. 許可教員は両アプリを利用でき、未許可・匿名・偽のメール申告は管理権限を得られない。
18. 共通マスターからの追加・無効化が両アプリへ反映され、一般教員は許可リストを変更・閲覧できない。
19. プロジェクトをまたぐ本人照合、管理元の障害、失効トークン、秘密署名不正、更新競合を検証する。
20. 共通認可追加後も、イオンコンペの既存教員ログイン・競技・結果・許可取り消しが動く。
21. 保存期限の表示、期限後のアクセス拒否、定期削除、子データ清掃、匿名Auth保護条件が動く。
22. 42名の同時参加、準備、解答送信、結果回収を計測する。複数クラスの同時利用は実際のプランと負荷結果から運用範囲を示し、42名の単一クラスの成功だけで保証しない。

### 12.4 ブラウザーと実機

23. Playwright MCPを優先し、ローカルで390px級のスマートフォン、タブレット、PCの配置、操作、console error、失敗した通信を確認する。公開が承認された段階では公開ページでも主要フローを確認する。
24. 実際のGoogleログインと共通許可リストは実サービスで検証し、ローカルの認証fixtureによる確認と区別する。
25. iPhone/iPadの長押し・ドラッグ・手書き・音は実機の確認項目として残し、ブラウザーのエミュレーションだけで合格としない。
