# 並べる：盤面操作によるブラウザバックの抑制仕様案

作成日: 2026-10-12。対象はCloudflare Lite版アルカンコンペ。同日に実装・公開の承認を受けて実装。自動検証と公開確認は `cloudflare-lite/docs/verification.md` に記録し、実機の履歴ジェスチャー確認は別途扱う。

## 目的と対応可否

生徒が「並べる」の解答グリッドをなぞる、配置済みパネルを移動する、パレットからグリッドへパネルを置く際に、操作がブラウザの戻る／進むジェスチャーとして扱われることを防ぐ。

既存のPointer Eventsによる盤面編集を維持し、ブラウザ側の既定動作だけを抑える構成は可能。ただし、ページへイベントが届かないOS・ブラウザ独自の画面端ジェスチャーまで、Webアプリから一律に停止できるとは保証しない。対象実機での合格確認を完了条件にする。

発生端末・OS・ブラウザは未特定のため、指・ペンによる操作とトラックパッドの横操作を確認対象とする。実際の環境が分かれば、その環境を最優先にする。

## 調査結果

- 現在の盤面とパレットには `touch-action: none` がある。盤面の `pointerdown` では `preventDefault()` と `setPointerCapture()` を実行している。
- 盤面編集はタップ回転、炭素のなぞり配置、400ms長押し移動、盤面外での削除に対応する。新しい入力方式に置き換える必要はない。
- ローカルの既存テスト環境を使ったChromium調査では、盤面上の `pointerdown` はキャンセルされているが、`touchstart`・`touchmove`・横方向の `wheel` はキャンセルされていなかった。
- 盤面は `overflow: visible`、盤面とページルートの `overscroll-behavior-x` は `auto`。非スクロールコンテナの盤面へoverscroll CSSだけを追加しても、仕様上は効果を期待できない。
- 上記のイベント調査はCDPのタッチ入力とブラウザのホイール入力によるもの。実iPad/iPhoneやmacOSのブラウザバック自体は再現・検証していない。現時点の判断は、抑制が不足する経路の特定と実装方針の評価まで。

## 仕様

### 1. 適用する画面・領域

- クラス・メイトの両方で、解答中の「並べる」へ適用する。
- 問題毎判定・まとめて判定・混合出題の並べる問題・再解答に適用する。
- タッチの抑制対象は解答グリッド全体（マス間の隙間・使用しないマスを含む）と、盤面へ置くパレットからの操作。
- 接続待ちや判定待ちで一時的に編集不可でも、並べるの解答画面が表示されている間は保護を維持する。
- 名付ける、全解答確認、提出確認、待機、結果、ホーム、教員設定へ切り替わったら追加保護を解除する。読み取り専用の構造表示には追加しない。

### 2. 指による操作の抑制

- 既存の `touch-action: none` とPointer Eventsの編集処理を維持する。
- 対象要素にネイティブの `touchstart`・`touchmove` リスナーを `{passive:false}` で登録する。キャンセル可能な単一タッチの既定動作を、操作開始から抑止する。
- Reactのイベント既定値に依存せず、DOM要素へ明示的に登録・解除する。
- 盤面から始めた操作が盤面外に出ても、同じ操作として扱う。長押し後の盤面外削除は従来通り行う。
- この補助処理で配置・回転・移動を実行しない。既存のPointer Eventsだけが編集データを更新し、二重配置・二重回転を防ぐ。

### 3. トラックパッド・横スクロールの抑制

- 対象の解答グリッド／パレット上の横成分を持つ `wheel` を、ネイティブの `{passive:false}` リスナーで抑止する。キャンセル可能な最初のイベントから対応する。
- 純粋な縦ホイールと、`ctrlKey` を伴うズーム相当の操作はこの処理では止めない。
- マウス・ペンのドラッグは従来のPointer Eventsを利用する。

### 4. ページルートの補助保護

- 並べるの解答画面が表示されている間だけ、ページルートに `overscroll-behavior-x: contain` を適用する。縦方向は変更しない。
- これはページ全体の横方向の履歴スワイプを抑える補助措置であり、盤面外の横スワイプも抑制対象になる。盤面外の縦スクロールと、戻るボタンによる操作は残す。
- 画面遷移・問題切替・アンマウント時に、変更前の設定へ戻す。アプリ全体に常時適用しない。
- 新たなスクロールコンテナや盤面のクリッピングを作らず、現在の寸法・化学構造の表示範囲を維持する。

### 5. 操作・データ・戻る操作

- タップ、逆回転、なぞり、400ms長押し、ドラッグ移動、盤面外削除、候補選択を維持する。
- キーボードによる配置・回転・削除、採点、端末保存、同期、再読み込み復元を維持する。
- ブラウザの戻るボタンや履歴移動キーは妨げない。履歴のダミー追加、戻った直後の強制前進、常時の離脱確認は追加しない。
- 設定項目・新しいボタン・恒常的な注意表示を追加しない。
- リスナーは対象表示期間だけ保持し、終了時に解除する。複数回の問題切替で増殖させない。

## 変更箇所

- `cloudflare-lite/game/client/AlkaneBoard.tsx`: 解答グリッドでのネイティブイベント保護。
- `cloudflare-lite/game/client/QuestionView.tsx`: パレットからのドラッグ保護。
- `cloudflare-lite/src/Player.tsx` と `cloudflare-lite/src/lite.css`: 現在の解答状態と問題モードに応じたページルート保護と復元。
- 必要なら同じ保護を盤面とパレットで使う小さな内部ヘルパーを置く。新しいライブラリ・汎用ジェスチャー基盤は導入しない。
- サーバー、認証、出題、採点、保存形式は変更しない。

## 受け入れ条件と検証

1. 左右のなぞり、斜めドラッグ、パレットからの配置、長押し移動・盤面外削除で、URL／表示画面／履歴位置が意図せず変わらない。
2. 空欄・配置済みマス・マス間の隙間・使用しないマスから始めた操作で同じ保護が働く。
3. 単発タップ・連続タップ・逆回転・候補選択・キャンセル・blurの処理が従来通りで、編集が二重発生しない。
4. 盤面外の縦スクロール、ブラウザの戻るボタン、全解答確認／結果画面での通常操作を追加保護が妨げない。
5. 並べる→名付ける、全解答確認への往復、競技終了、ホームへ戻る操作で保護が解除・再設定される。ルートCSSやイベントリスナーが残らない。
6. 下書き同期・再読み込み復元・提出・結果表示が従来通り動く。
7. Chromium／WebKitの自動検査で、イベントキャンセル、既存の盤面操作、画面遷移後の解除、縦スクロール、console／ネットワークエラーを確認する。自動入力だけでブラウザ固有の履歴ジェスチャーが止まると判断しない。
8. 発生端末の実機で、指／ペン／トラックパッドの該当操作と画面端からの操作を確認する。iPad/iPhoneはSafariと利用中のブラウザ、Macは利用中のブラウザを対象にする。OS／ブラウザの版を記録する。

実機でページに届かない画面端操作が残る場合は、その事実を制約として報告する。履歴の書き換えで見かけ上戻れなくする方法へ拡張しない。

## 根拠

- [W3C Pointer Events: touch-action](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property): touch-actionは直接操作のパン・ズームを制御する。既存Pointer Eventsの処理を維持する根拠。
- [CSS Overscroll Behavior（2026-06-30編集者草案）](https://drafts.csswg.org/css-overscroll-1/): containによる履歴ジェスチャー等の境界動作の抑制と、非スクロールコンテナでは無効となる規定。使用するcontainは既存の実装を前提とし、草案の新しい値は使わない。
- [WebKit #240892](https://bugs.webkit.org/show_bug.cgi?id=240892): iOSのtouchstartとmacOSのwheelによる補助対策の報告。2022年の報告であり、現在の対象実機の合格証拠ではない。
- [Flutter #114324（2026-09-25調査コメント）](https://github.com/flutter/flutter/issues/114324): iOS Safariの画面端履歴スワイプがtouch-action:noneだけでは止まらず、touchstartキャンセルが必要となる事例。Flutterの二重画面問題をこのReactアプリの原因とは扱わない。
